## Storage, independently of transport

- Current release volume is 5 GB and nearly full. Preserve active/rollback artifacts;
  choose expansion size from inventory plus two release sets and 30% spare.
  Railway CLI/public API inspected here did not expose volume resizing. Use the
  Railway volume dashboard; never detach/replace the mounted volume to simulate a resize.
- Run `php artisan vibyra:release-capacity --incoming-bytes=<planned-total>` before
  upload. Warning at 80%, critical at 90%; upload requires at least 512 MiB or 10%
  remaining, whichever is larger. Target 30% spare operationally.
- Optional private S3-compatible disk uses `VIBYRA_RELEASE_ACCESS_KEY_ID`,
  `VIBYRA_RELEASE_SECRET_ACCESS_KEY`, `VIBYRA_RELEASE_REGION`,
  `VIBYRA_RELEASE_BUCKET`, `VIBYRA_RELEASE_ENDPOINT`, `VIBYRA_RELEASE_PATH_STYLE`.
  Verify exact environment names against `config/filesystems.php` before entering
  credentials via the provider's secret UI. Do not paste secrets into chat/logs.
- Inventory with `php artisan vibyra:release-storage-copy release-object`.
  Copy with the same command plus `--execute`; readback size and SHA-256 must match.
  Conflicting destination bytes fail rather than overwrite. Originals remain.
- Set `VIBYRA_RELEASE_DISK=release-object`, `VIBYRA_RELEASE_FALLBACK_DISK=local`
  only after full/range/conditional authenticated downloads and signed updater
  metadata match. Roll back reads to `local`; retain originals through observation.
  The existing uploader remains volume-based; do not delete newly uploaded local
  files until verified object copy. Schedule alert delivery from capacity log events.

## Authorization, relay and compatible Mac

Stage the whole set first with dedicated accounts and isolated database. Apply the
additive generation/challenge/outbox migration. Never roll back by restoring
unproved transfers or stale-token admission.

Prepare the compatible signed Mac build before the enforcement rollout. Current
clients require the new challenge API; old clients fail closed after enforcement.
Use a coordinated maintenance window or a separately reviewed staged client release;
there is no unbounded legacy bypass. Do not describe this as a zero-downtime upgrade.

Deploy API then relay then activate the compatible Mac during that window. Relay
requires `VIBYRA_API_URL` and matching signing/report/admin credentials; keep one
replica, bind publicly as configured for Railway, and confirm actual `/health`
healthcheck settings. Existing Cloud sockets reconnect during replacement.
Check protected `/admin/diagnostics` without logging bearer tokens.

Credential separation uses matching API/relay values for
`VIBYRA_RELAY_SIGNING_SECRET`, `VIBYRA_RELAY_ADMIN_SECRET`, and
`VIBYRA_RELAY_REPORT_SECRET`; legacy `VIBYRA_RELAY_SECRET` remains a migration fallback.
Signing rotation uses `VIBYRA_RELAY_SIGNING_KEY_ID`, previous secret/key ID and an
explicit Unix-seconds `VIBYRA_RELAY_SIGNING_PREVIOUS_UNTIL` deadline on both services.
Verify old-key overlap, new-key issuance and expiry rejection in staging before
production. Remove previous key after the chosen overlap. Never leave an indefinite
previous secret. Admin/report rotation needs coordinated values; there is no dual-key
acceptance for those credentials.

Verify registration, explicit transfer, current generation pairing, logout/expiry,
revocation while admin delivery fails, relay restart, delayed presence and 180-second
maximum API-outage lease. Run the scheduler for outbox retries; keep its instance
count one. Queue workers must cover vibes, decisions, notifications, deployments
and default. Never send long provider work into the reserved control pool.

## Optional web capacity, separate release

Keep `VIBYRA_WEB_SERVER=builtin` until the Linux image passes real application
stream/upload/cancel/download/auth tests and measured resource limits.
The opt-in is `VIBYRA_WEB_SERVER=fpm`, `VIBYRA_WEB_WORKERS=8`,
`VIBYRA_CONTROL_WORKERS=2` initially. Set an existing non-root `VIBYRA_FPM_USER`
and matching `VIBYRA_FPM_GROUP` when launching as root, and make only Laravel runtime
paths writable by that identity. Startup checks refuse unsafe/unwritable ownership.
Validate nginx/php-fpm paths in the built image. Rollback only this setting to builtin
if needed; preserve authorization fixes and migration. Size worker/DB/memory capacity
from load evidence before adding replicas. Relay scaling remains disabled until
host-to-replica routing and fenced failover exist.
