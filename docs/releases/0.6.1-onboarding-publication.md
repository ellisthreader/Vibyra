# Vibyra 0.6.1 — phone companion onboarding

Published source: `6485f8c920acaf81964fbb3e81f9a7e6421cb72c`.
The later documentation/test-only follow-up does not change packaged application code.

## User-facing changes

- The new `mobile/` phone/web client starts with a welcome screen, **Connect computer**,
  a labelled sample workspace, and **Set up later**. No Vibyra account is required
  for this standalone Host preview. Setup can be reopened in Settings.
- Welcome completion persists locally; browsing sample content does not complete
  setup or authorize a device. Storage failures remain recoverable.
- Desktop **Settings → Phone companion (WIP)** and the command palette open setup,
  Host downloads, and reviewable Windows PowerShell/Linux commands for a chosen
  project and private Wi-Fi address. Native resource opening uses a fixed allowlist.
- WIP status remains visible. Computer approval is still mandatory. Closing a
  pending pairing cancels it; retry uses a fresh single-use invitation from `pair`.
- Hosted HTTPS rejects a local ws link before enrollment and explains the native
  phone/local-web alternative or the need for a provisioned secure wss endpoint.

## Validation and limits

- Desktop: 777 frontend tests, build/typecheck, line/dead-code gates, native
  fmt/clippy/tests, three platform package/launch gates and signed-set verification.
- Mobile: 29 tests, typecheck, native/web export and 75 files within the 200-line gate.
- Real browser checks: four onboarding layouts, light/dark workspace journeys,
  skip persistence, sample isolation, storage failure, setup recovery and navigation.
- Real Host: cancellation before approval, fresh invitation retry, approved pairing,
  two independent terminals/drafts, command/file effects, file/diff review,
  disconnect/reconnect, observation/control and session stopping.
- Desktop setup browser checks use mocked IPC; native resource policy is tested
  separately in Rust. Local native build ran out of build-disk space; CI native
  gates and actual packaged launch checks supplied the native validation.
- Existing Desktop chat synchronization, automatic Host installation, public relay
  enrollment, native store distribution and physical iPhone qualification remain WIP.
  The hosted browser needs wss; local phone testing uses the native preview or HTTP web.
