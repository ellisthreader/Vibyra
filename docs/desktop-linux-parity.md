# Desktop Mac and Linux parity

The reference for this port is the installed `/Applications/Vibyra.app` 0.7.8 build 8, with native executable SHA-256 `711e17a5612987fdac9dc3ec1fc8d0ab523e404094731246452346dbb0a90f9d`. The `release/macos-0.7.8` branch has a different binary and frontend despite the same version label. Version alone cannot identify the shipped UI.

The installed native executable contains 85 reachable frontend assets. The decoded Brotli payloads were matched byte-for-byte to its Tauri codegen asset records; the extracted frontend digest is `aee902821ee3f21eb541baf7f89f39b8427150c1c99a3e48f7ec496d9a7ae43d`. The reference extraction and receipt are local review inputs, not release inputs. They live outside the checkout at `/private/tmp/vibyra-installed-078-frontend/` and its `.tar.gz` archive. A fresh extraction should check the binary SHA before comparing anything.

The Linux build uses the same React components, layout styles, themes, bundled artwork, and product flows as the Mac build. Linux-specific changes are isolated to native GTK/window-manager decorations, platform labels and shortcut routing, native process/audio/screenshot APIs, packaging, and system integration. The Mac system-font override is preserved, while Linux uses bundled Inter. The original 0.8 review found all 3,151 installed Mac stylesheet rules in the candidate plus 13 Linux-only rules; the native-title-bar fix removes those Mac-style Linux window-control rules. The original rule-level comparison is recorded in `output/linux-parity-preview/final-css-differences.json` when the local review is run.

`npm --prefix desktop-tauri run review:parity` serves the real application components with disposable IPC data. With `VIBYRA_MAC_REFERENCE_DIST` pointing to the extracted `dist`, `/compare` also mounts the unmodified installed Mac assets in a second frame. Sign-in, Agents, and four-pane workspace surfaces have been compared in Safari at 960 or 1280 × 800. The structure, artwork, spacing, and controls match, aside from the OS label and Linux controls. Native Linux rasterization must be reviewed on WebKitGTK, not inferred from Safari.

Native Linux implementation includes `/proc`-scoped Codex session identity discovery, in-memory ALSA dictation, speech playback through `espeak-ng`, portal screenshot capture on Wayland, AppImage-safe child process environment, desktop entry installation, and every IPC endpoint invoked by this frontend. F8/F9/F10 and configured keys have a focused-window fallback on Wayland because the pinned native global-hotkey library uses X11; compositor-global activation on Wayland remains a separate integration requirement.

The shared frontend workflow `.github/workflows/desktop-frontend.yml` produces one asset archive and hash manifest for Mac and Linux release packaging. The Ubuntu CI workflow `.github/workflows/desktop-tauri.yml` runs the source, frontend, Rust, security and packaging gates, then starts the actual AppImage under WebKitWebDriver to capture sign-in and email navigation. A passing source build on macOS is not evidence that the Linux AppImage launches. Track the actual workflow run, artifact SHA and screenshot before declaring release parity. Its unsigned CI package is only a candidate; the public release uses the signed `.github/workflows/desktop-release.yml` artifacts.

The public `v0.8.0` Linux release was built from `ee9a178a94fc8fc51ae62237d20df80dc658ff20` in workflow run `35846019554`. The Linux job passed its source gates, signed both x86_64 AppImage and Debian packages, and smoke-tested the AppImage's native version IPC, bundled assets, sign-in, and email navigation. The AppImage SHA-256 is `0d66b81c3eeacb39a17d05364de017b51647fe733d9a7f05ded90c12c49e6784`; the Debian package SHA-256 is `9d791904991826ecdebd6f9b6f3ccaa675ee6dc9c691a6fc3330ce2edb937b56`. Both updater signatures were verified against the shipped public key before deployment, and the production `/web-api/releases` and `/web-api/updates/linux/x86_64/{appimage,deb}/0.6.3` routes were checked after deployment. The all-platform workflow run is red because its Windows Linux-launcher-path test and Mac signing jobs failed; the Linux job itself is green.

Local checks: `npm run lines`, `npm run check:dead-code`, `npm test`, `npm run build`, `npm run rust:fmt`, `npm run rust:clippy`, and `npm run rust:test` from `desktop-tauri/`. For Linux, use `desktop-tauri/scripts/setup-linux.sh --ci`, build the AppImage with `npm run app:build:linux`, and run `scripts/smoke-linux.mjs` with Xvfb and WebKitWebDriver. Avoid checking generated `dist`, `target`, or the extracted reference into the repository.
