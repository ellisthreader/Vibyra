# Desktop Mac and Linux parity

The reference for this port is the installed `/Applications/Vibyra.app` 0.7.8 build 8, with native executable SHA-256 `711e17a5612987fdac9dc3ec1fc8d0ab523e404094731246452346dbb0a90f9d`. The `release/macos-0.7.8` branch has a different binary and frontend despite the same version label. Version alone cannot identify the shipped UI.

The installed native executable contains 85 reachable frontend assets. The decoded Brotli payloads were matched byte-for-byte to its Tauri codegen asset records; the extracted frontend digest is `aee902821ee3f21eb541baf7f89f39b8427150c1c99a3e48f7ec496d9a7ae43d`. The reference extraction and receipt are local review inputs, not release inputs. They live outside the checkout at `/private/tmp/vibyra-installed-078-frontend/` and its `.tar.gz` archive. A fresh extraction should check the binary SHA before comparing anything.

The Linux build uses the same React components, layout styles, themes, bundled artwork, and product flows as the Mac build. Linux-specific changes are isolated to window controls, platform labels and shortcut routing, native process/audio/screenshot APIs, packaging, and system integration. The candidate CSS has 3,145 declarations/rules identical as a multiset to the 3,151-rule installed Mac sheet. The six replaced rules are three Mac-only selectors extended to Linux, the Mac system-font token replaced with shared bundled Inter, and two text surfaces switched to that shared font token. The candidate adds nine rules for the Linux leading window controls. These differences are recorded in `output/linux-parity-preview/final-css-differences.json` when the local review is run.

`npm --prefix desktop-tauri run review:parity` serves the real application components with disposable IPC data. With `VIBYRA_MAC_REFERENCE_DIST` pointing to the extracted `dist`, `/compare` can also mount the unmodified installed Mac assets in a second frame. The sign-in surface has been compared in Safari at 1280 × 800: the structure, artwork, spacing, and controls match, aside from the OS label and Linux controls. The installed app's workspace boot effects make its sample project restoration harder to reproduce; do not infer a product mismatch from that fixture's home screen until both frames show the same state. Native Linux rasterization must be reviewed on WebKitGTK, not inferred from Safari.

Native Linux implementation includes `/proc`-scoped Codex session identity discovery, in-memory ALSA dictation, speech playback through `espeak-ng`, portal screenshot capture on Wayland, AppImage-safe child process environment, desktop entry installation, and every IPC endpoint invoked by this frontend. F8/F9/F10 and configured keys have a focused-window fallback on Wayland because the pinned native global-hotkey library uses X11; compositor-global activation on Wayland remains a separate integration requirement.

The shared frontend workflow `.github/workflows/desktop-frontend.yml` produces one asset archive and hash manifest for Mac and Linux release packaging. The Ubuntu CI workflow `.github/workflows/desktop-tauri.yml` runs the source, frontend, Rust, security and packaging gates, then starts the actual AppImage under WebKitWebDriver to capture sign-in and email navigation. A passing source build on macOS is not evidence that the Linux AppImage launches. Track the actual workflow run, artifact SHA and screenshot before declaring release parity. The package is unsigned and is a candidate until that runtime check passes.

Local checks: `npm run lines`, `npm run check:dead-code`, `npm test`, `npm run build`, `npm run rust:fmt`, `npm run rust:clippy`, and `npm run rust:test` from `desktop-tauri/`. For Linux, use `desktop-tauri/scripts/setup-linux.sh --ci`, build the AppImage with `npm run app:build:linux`, and run `scripts/smoke-linux.mjs` with Xvfb and WebKitWebDriver. Avoid checking generated `dist`, `target`, or the extracted reference into the repository.
